title: "x86 與 CPU 基礎"

**OS 的很多機制其實是 CPU 提供的：權限等級讓 kernel 和程式分開，中斷讓 OS 能把 CPU 搶回來，MMU 讓虛擬記憶體成立。** 這頁整理寫後端時需要知道的 CPU 概念，以 x86-64 為主。

## ISA：x86 vs. ARM

ISA（Instruction Set Architecture）是 CPU 看得懂的指令集，編譯出來的執行檔只能在相同 ISA 的 CPU 上跑。

| | x86-64（amd64） | ARM64（aarch64） |
| --- | --- | --- |
| 設計 | CISC：指令多、長度不固定 | RISC：指令精簡、長度固定 |
| 常見於 | 大部分伺服器、PC | 手機、Apple Silicon、AWS Graviton |
| 特色 | 相容性好，生態系成熟 | 省電，同效能下成本常較低 |

實務上會遇到的：

- 在 Apple Silicon 上 build 的 Docker image 預設是 `arm64`，丟到 x86 伺服器上會 `exec format error`。用 `docker buildx build --platform linux/amd64,linux/arm64` 一次 build 多架構。
- Go 跨平台編譯：`GOOS=linux GOARCH=amd64 go build`。
- Rust：`cargo build --target x86_64-unknown-linux-gnu`。

## Privilege Ring

x86 有 4 個權限等級（ring 0 ~ 3），實務上只用兩個：

```text
Ring 0：kernel mode，可以執行所有指令、存取所有記憶體
Ring 3：user mode，不能直接操作硬體、不能改 page table
```

User mode 的程式執行特權指令會觸發例外，被 kernel 處理（通常是殺掉該 process）。要做特權的事只能透過 **system call**，在 x86-64 上是 `syscall` 指令：把 system call 編號放在 `rax`、參數放在 `rdi`、`rsi`、`rdx`… 再執行 `syscall`，CPU 會切到 ring 0 跳到 kernel 預先設定好的入口。

虛擬化需要讓 guest OS 以為自己在 ring 0，Intel VT-x / AMD-V 為此加了額外的模式，讓 hypervisor 管理 guest。

## 中斷（Interrupt）

中斷讓 CPU 暫停目前的工作，去執行對應的處理程式（interrupt handler）。

| 類型 | 來源 | 例子 |
| --- | --- | --- |
| 硬體中斷 | 外部裝置 | 網卡收到封包、磁碟 I/O 完成、鍵盤輸入 |
| Timer 中斷 | 計時器 | 時間片用完，OS 藉此做排程 |
| 例外（Exception） | CPU 執行指令時發生 | page fault、除以零、執行非法指令 |
| 軟體中斷 / trap | 程式主動觸發 | 舊式的 `int 0x80` system call |

**Timer 中斷是 preemptive multitasking 的基礎**：就算某個程式寫了無窮迴圈，timer 一到 CPU 還是會回到 kernel，讓 scheduler 換別人跑。

高流量時網卡中斷太多會吃掉大量 CPU，所以 Linux 用 **NAPI**（流量大時改成輪詢）、**RSS / IRQ affinity**（把中斷分散到多顆 CPU）來緩解。可以用 `cat /proc/interrupts` 觀察。

## 暫存器與 Calling Convention

x86-64 有 16 個 64-bit 通用暫存器：

| 暫存器 | 常見用途（System V AMD64 ABI，Linux / macOS） |
| --- | --- |
| `rax` | 回傳值；system call 編號 |
| `rdi`、`rsi`、`rdx`、`rcx`、`r8`、`r9` | 函式的前 6 個整數參數 |
| `rsp` | stack pointer，指向 stack 頂端 |
| `rbp` | frame pointer（可省略） |
| `rip` | instruction pointer，下一條要執行的指令 |

函式呼叫時，`call` 指令把返回位址推進 stack 再跳過去，`ret` 再把它取出來跳回去。Buffer overflow 攻擊就是蓋掉 stack 上的返回位址，讓 `ret` 跳到攻擊者的程式碼；所以有 stack canary、NX bit、ASLR 等防護。

看 Go 產生的組語：`go build -gcflags=-S`，或用 [Compiler Explorer](https://godbolt.org/)。

## 多核心與 Cache

- 每顆核心有自己的 L1 / L2 cache，L3 通常共用（見 [Memory](/os/memory#記憶體階層)）。
- **Cache coherence**：一顆核心改了某個值，其他核心 cache 裡的舊值要失效（MESI 協定），這個同步有成本。
- **False sharing**：兩個 thread 各自改不同的變數，但它們剛好在同一條 64-byte 的 cache line 上，cache line 就會在兩顆核心之間來回失效，效能大幅下降。解法是 padding，讓熱點變數各自佔一條 cache line。
- **NUMA**：多插槽伺服器上，每顆 CPU 有自己「近」的記憶體，存取別顆 CPU 的記憶體比較慢。資料庫等大型服務要注意 NUMA 配置（`numactl`）。
- **Hyper-Threading（SMT）**：一顆實體核心模擬成兩個邏輯核心，共用執行單元。`nproc` 看到的是邏輯核心數。

## Endianness

多 byte 的數字在記憶體裡怎麼排：

```text
0x12345678
Big-endian：    12 34 56 78   （高位在前；網路傳輸用，network byte order）
Little-endian： 78 56 34 12   （低位在前；x86、多數 ARM）
```

寫網路協定或解析二進位格式時要注意，例如 Go 的 `binary.BigEndian.Uint32()`。

## 一句話總結

> CPU 用 ring 0 / ring 3 分開 kernel 和程式，`syscall` 是兩者之間的門。Timer 中斷讓 OS 能搶回 CPU 做排程。多核心之間要維持 cache 一致，所以要小心 false sharing。Build image 時注意 amd64 和 arm64。
